# RC UI 风格 2.0

**版本：2.0。** 原有六项视觉特征继续有效；新增 UI 文案约束与动效连续性要求。

## 先识别当前任务

- 检查目标界面的现有主题、组件、样式加载顺序和最终覆盖值。修改已有项目时，优先延续其语言，不用本包整体替换局部修复。
- 区分紧凑悬浮工具、内容图库、桌面设置面板、数据仪表盘与展示首页，再选择密度和容器层级。
- 优先看 [2.0 参考图](assets/style-reference-v2.webp) 判断布局与材质组合；[历史确认图](assets/style-confirmation.png) 仅作风格来源。图中的文字、模拟数据和图标都不是可复制的产品规范。
- 确认图仍写“待你确认”，但整体方向已于2026-10-29获用户确认。图中深色缩略图是示意，不允许因此压暗真实媒体；正文规则优先于生成图的伪影。
- 功能要求及用户本次指示优先于风格默认值。本 skill 不授权仓库推送、部署、删除或无关重构。

## 2.0 文案强制规则

- 阅读 [UI 文案规范](references/content-style.md)。所有新 UI 文案只说明**功能、对象、动作、结果或限制**，使用短句和稳定术语，不加修饰性语言、广告口号、情绪化感叹或无意义的提示。
- 标题写模块名称；按钮写动作与必要对象；状态写真实结果。错误提供恢复入口，高风险动作保留完整提示。不得为了缩短文案而删除安全、无障碍或业务信息。
- 示例：“进入精彩的影像世界” → “作品图库”；“为你精心准备中” → “加载中”；“奇迹般完成” → “已完成”。不要把参考图中的英文口号当作生产文案。
- restrained / expressive / showcase 三档仅控制视觉与动效，不改变文案要求。提交前检查按钮、导航、提示、空状态、加载、错误、成功和示例内容。

## 保持六个核心特征

1. **轻玻璃而非重装饰**：半透明磨砂、1px 细边、柔和低层级阴影。保证文字和真实内容清晰，不全屏堆叠模糊。
2. **有层级的圆角矩形**：控件小、卡片中、面板大；胶囊主要留给状态、筛选与进度。保留已有项目的导航胶囊例外。
3. **紧凑但不挤**：统一图标尺寸、文字基线、控件高度和间距。数字右对齐或使用等宽数字；不要为显得高级而增加空白或营销巨标题。
4. **强调色可换**：浅色冷白、深色灰蓝是可用方向，不强制双主题。蓝、青、灰紫、玫瑰都可承载品牌；危险/警告/成功语义色保持独立。
5. **反馈可感知但克制**：悬停轻增亮或小幅抬升，按下轻回落或轻缩放，焦点清楚；不要全局叠加所有效果。
6. **动作有原因**：选中底板平滑滑动、面板淡入小位移、少量轻弹性。业务忙碌与进度必须来自真实状态；装饰氛围单独选择、可关闭，不能暗示后台正在工作。

## 先选用途、强度与降级

应用增强效果前，读取 [效果目录与证据](references/kiseki-effects.md)，对每个候选填写“服务什么任务 / 选用强度 / 无动效或低性能替代”。已有界面的局部修复沿用当前档位；不为套用参考站而整体升档。

| 强度档 | 适用界面 | 默认选择 |
|---|---|---|
| `restrained` | 高频工具、编辑器、设置、紧凑桌面浮层 | 沿用六核心；短反馈、清晰状态、少量切换，不默认持续装饰 |
| `expressive` | 媒体图库、内容页、仪表盘 | 在可读基底上选择局部光晕、导航岛、Bento、内容过渡；逐项启用 |
| `showcase` | 个人主页、作品入口、短时展示页 | 允许更明显的环境层、局部视差、首屏编排；保留立即可用的内容与关闭入口 |

- 将强度、材质、主题分开选择。`glass / solid / outline` 是材质选项，`flat` 用于高密度或降级；`light / dark` 是项目已有主题，不用切换材质强制改变主题。
- 每个视口先确定一个主要氛围系统，每个交互目标确定一种主反馈，再判断是否需要辅助效果；不要同时启用目录中所有装饰。为内容型页面选择 `expressive` 也不等于全部控件发光。
- 光标聚光、倾斜或局部视差只做渐进增强；触摸、键盘、减少动效、页面隐藏和低性能都有等效静态状态。不得接管系统光标、锁住滚动或让内容等待动画。
- 从目录选定后，读 [实现配方与接口](references/effects-recipes.md)，映射到目标框架。使用可选资产时沿用其显式初始化与销毁约定，覆盖多个 root、重复挂载和运行时偏好变化。
- 优先保证业务正确、焦点与可读性、媒体原色和性能，再调整表现强度。记录未采用效果的任务原因，而不是机械凑齐效果数量。

## 按需读取并实施

- 选色、材质、圆角、字体与间距：读 [视觉系统](references/visual-system.md)。
- 按钮、输入、导航、卡片及状态：读 [组件规则](references/components.md)。
- 基础时长与项目例外：读 [动效规则](references/motion.md)；2.0 场景切换、图表和面板必须读 [连续性规范](references/motion-v2.md)。
- 氛围、材质切换、光标聚光、局部视差、导航岛、Bento、媒体联动与内容编排：先读 [效果目录](references/kiseki-effects.md)，再读 [实现配方](references/effects-recipes.md)。目录中的观测、源码证据与 RC 合成建议必须分开。
- 新界面可从 [局部 CSS 模板](assets/rc-ui.css) 和 [组件示例](assets/components.html) 选取片段；已有项目映射到自身 token，不无条件导入。
- 需要增强实现时，按 [实现配方](references/effects-recipes.md) 选用 [效果 CSS](assets/rc-effects.css)、[效果脚本](assets/rc-effects.js) 和 [效果示例](assets/effects.html)。保留原基础模板的可用性；示例数据与播放器状态不冒充真实业务。
- 遇到风格冲突或需要复刻具体参考项目：读 [来源与例外](references/source-map.md)，查当前实现后再决定，不把历史数值当永久事实。
- 检查新 UI 文案时读取 [文案规范](references/content-style.md)，保证短句、无装饰、状态准确。
- 完成后用 [验收与独立评分](references/acceptance.md) 检查有关项目。尝试启用可用的独立子线程/子代理，按布局、视觉、按钮、动效、可访问性等模块分工审查；按任务规模合并模块，不固定开启数量。向评审提供需求与原始证据，不提供作者自评或预期结论。
- 汇总模块评分、证据覆盖率与阻断项，修复后复验受影响模块。评分不代替运行验证，未测试项目标记未验证；代理不可用时明确采用单代理检查，不假称独立评审。具体量表、交接与报告模板见验收文档。

## 推荐交付方式

说明项目形态、强度档、材质与主题、采用的效果及其降级、关键 token 和保留的例外；提供目标视口截图及交互/动效验证结果。没有视觉运行条件时明确限制，仍可完成代码与规则检查。用户没有要求整体重设计时，保持改动范围最小。
