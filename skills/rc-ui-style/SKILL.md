# RC UI 风格

## 先识别当前任务

- 检查目标界面的现有主题、组件、样式加载顺序和最终覆盖值。修改已有项目时，优先延续其语言，不用本包整体替换局部修复。
- 区分紧凑悬浮工具、内容图库、桌面设置面板与数据仪表盘，再选择密度和容器层级。
- 使用 [确认图](assets/style-confirmation.png) 理解气质，不将生成图的文字、比例、色值当精确规格。用户确认的是整体方向；下述数值是可调基准。
- 确认图仍写“待你确认”，但整体方向已于2026-10-29获用户确认。图中深色缩略图是示意，不允许因此压暗真实媒体；正文规则优先于生成图的伪影。
- 功能要求及用户本次指示优先于风格默认值。本 skill 不授权仓库推送、部署、删除或无关重构。

## 保持六个核心特征

1. **轻玻璃而非重装饰**：半透明磨砂、1px 细边、柔和低层级阴影。保证文字和真实内容清晰，不全屏堆叠模糊。
2. **有层级的圆角矩形**：控件小、卡片中、面板大；胶囊主要留给状态、筛选与进度。保留已有项目的导航胶囊例外。
3. **紧凑但不挤**：统一图标尺寸、文字基线、控件高度和间距。数字右对齐或使用等宽数字；不要为显得高级而增加空白或营销巨标题。
4. **强调色可换**：浅色冷白、深色灰蓝是可用方向，不强制双主题。蓝、青、灰紫、玫瑰都可承载品牌；危险/警告/成功语义色保持独立。
5. **反馈可感知但克制**：悬停轻增亮或小幅抬升，按下轻回落或轻缩放，焦点清楚；不要全局叠加所有效果。
6. **动作有原因**：选中底板平滑滑动、面板淡入小位移、少量轻弹性。只有真实任务才显示忙碌、呼吸或进度；不伪造后台工作。

## 按需读取并实施

- 选色、材质、圆角、字体与间距：读 [视觉系统](references/visual-system.md)。
- 按钮、输入、导航、卡片及状态：读 [组件规则](references/components.md)。
- 时长、缓动、展开收起与性能回退：读 [动效规则](references/motion.md)。
- 新界面可从 [局部 CSS 模板](assets/rc-ui.css) 和 [组件示例](assets/components.html) 选取片段；已有项目映射到自身 token，不无条件导入。
- 遇到风格冲突或需要复刻具体参考项目：读 [来源与例外](references/source-map.md)，查当前实现后再决定，不把历史数值当永久事实。
- 完成后用 [验收与独立评分](references/acceptance.md) 检查有关项目。尝试启用可用的独立子线程/子代理，按布局、视觉、按钮、动效、可访问性等模块分工审查；按任务规模合并模块，不固定开启数量。向评审提供需求与原始证据，不提供作者自评或预期结论。
- 汇总模块评分、证据覆盖率与阻断项，修复后复验受影响模块。评分不代替运行验证，未测试项目标记未验证；代理不可用时明确采用单代理检查，不假称独立评审。具体量表、交接与报告模板见验收文档。

## 推荐交付方式

说明采用的项目形态、关键 token 和保留的例外；提供目标视口截图及交互/动效验证结果。没有视觉运行条件时明确限制，仍可完成代码与规则检查。用户没有要求整体重设计时，保持改动范围最小。
