# 验收清单

按实际修改范围选择。截图和浏览器交互未运行时标为“未验证”，不能用单元测试替代视觉证据。

## 视觉

- [ ] 检查目标桌面、紧凑窗口、移动/触控尺寸；若涉及超宽图库，检查3440或目标实际宽度。
- [ ] 主次文字、图标、数字、按钮同一基线；同类控件高度/圆角一致。
- [ ] 面板与内嵌圆角有层级；胶囊没有无差别扩散。
- [ ] 边框细且可见，玻璃不影响文字；浅/深模式只在项目支持或本次要求时覆盖。
- [ ] 长标题、多行说明、空值、大数字、非ASCII文件名不破坏布局。
- [ ] 标签、收藏、更多菜单、滚动条不重叠；溢出只发生在预期滚动区域。
- [ ] 强调色更换不改变危险/成功语义；透明背景上的对比度经实际叠底检查。

## 状态与操作

- [ ] 按钮常态、hover、press、focus-visible、disabled、loading都可区分。
- [ ] 键盘可达且焦点可见；图标按钮有名称；tabs/过滤器语义正确。
- [ ] Loading防重入符合业务，失败、取消与部分成功可恢复，不伪造进度。
- [ ] 浮层关闭、ESC、外部点击、再次打开与焦点回退正确；hover不是唯一入口。
- [ ] 连续快速点击、切换中关闭、反复展开收起不会残留半透明或错误高度。
- [ ] 主动编辑、复制时得到完整真实内容，不被文本呈现动效截断。

## 动效与可访问性

- [ ] 动效服务状态变化，按下不造成周围布局跳动。
- [ ] 选中底板在文本/字体/resize变化后仍对齐。
- [ ] reduced-motion下无位置/缩放/弹性/装饰循环，信息仍完整。
- [ ] 低性能/不支持backdrop-filter时有可读实色回退。
- [ ] 触控命中区域足够，桌面紧凑视觉不必机械放大。
- [ ] 放大至200%时关键内容仍可访问；工具栏不遮挡主要操作。

## 交付结论

分列“已通过 / 发现问题 / 尚未验证”，列明实际视口、主题和测试手段。说明采用的token与项目例外。未经授权不为了补视觉效果修改业务、发布设置或其他项目。


## 独立子线程 / 子代理验收

### 启动与分工

检查当前环境是否提供独立子线程或子代理。可用时尝试启动独立评审，按改动范围划分下列模块；小改动可以把相关模块交给同一评审，不为了形式固定开六个代理。复杂界面可并行分工，避免多人重复操作同一个浏览器或修改同一文件。

| 模块 | 主要检查对象 | 典型证据 |
|---|---|---|
| 布局与响应式 | 对齐、密度、溢出、长文本、超宽/小屏、遮挡 | 标注视口和缩放的截图、DOM尺寸 |
| 圆角、材质与排版 | 层级、细边框、玻璃可读性、字号/字重/图标基线 | 截图、计算样式、最终token |
| 配色与语义 | 浅深色、强调色替换、状态色、真实媒体原色 | 实际叠底截图、对比度数据、主题值 |
| 按钮、状态与键盘 | hover/press/focus/禁用/加载、tabs、浮层、重复点击 | 可复现操作记录、状态/焦点轨迹 |
| 动效与中断 | 时长/缓动、小位移、轻弹性、底板测量、快速开关、真实忙碌 | 录屏、时间线、动画状态或运行轨迹 |
| 可访问性与性能 | 名称/角色、触控命中、200%缩放、减少动效、低性能回退 | 键盘/无障碍树、媒体查询/性能记录 |

评审默认只读。需要截图或本地测试时使用隔离测试数据；不得为验收对真实数据执行删除、提交或发布。评审发现问题后由主线程协调授权范围内的修复。

若代理入口不可用、启动失败或并发受限，继续单代理验收或串行独立评审，报告实际使用方式。不能把同一代理换一个标题写出的分数称作独立评价；外部网络/浏览器不可用也不能包装成运行通过。

### 证据驱动评分

每个适用模块使用 **0–5分**：

| 分数 | 条件 |
|---|---|
| 5 | 相关验收项均有对应证据通过，未发现实质偏差 |
| 4 | 主要行为与风格一致，仅有不影响任务完成的轻微问题 |
| 3 | 有明确中等问题或局部不一致，需要修正后验收 |
| 2 | 存在重要缺陷，核心模块有明显失效或严重偏离 |
| 1 | 多项主要行为失效，仅少部分可用 |
| 0 | 有充分证据表明模块不可用或验收核心目标完全失败 |

- **没有测试不是0分，也不是5分**。没有有效证据时写“未验证”，分数为N/A。与本次改动无关则写“不适用”，同样为N/A但注明理由。
- 某模块只查了源码时，可给“静态评分”并明确范围；运行评分保持N/A。禁止将静态评分混进运行总分或用它证明真实动效/布局通过。
- 部分用例已测时，可给有证据部分的“暂定分”，列出未测项；最高不直接标为完整5分。暂定分不进入最终总分。
- 完整模块的可选综合分为 `已完整验证模块分数之和 / (5 × 已完整验证模块数) × 100`。没有完整模块则综合分N/A。这个数值只描述已覆盖部分，不代表全界面质量。
- **覆盖率单列**：已验证适用检查项 / 全部适用检查项；另列完整模块数 / 适用模块数。静态与运行分别统计，同一项不重复计数。列出检查项清单，不能为提高覆盖率随意缩小分母。
- 不设“平均分达到某值就自动通过”。任务核心行为失败、无法完成主要操作、严重焦点/可读性问题、错误的数据或状态提示属于阻断项，无论平均分多高都不通过。
- 必要运行项尚未验证时结论写“部分通过，仍待验证”，而不是“验收通过”。评分不提供部署、推送或数据操作的额外授权。

### 保持评审独立

给评审本次需求、批准的风格、目标模块、固定提交/文件、原始截图/录屏/日志和可运行方式。**不传作者自评、期望分数、希望它确认的结论或别的评审的评分。** 评审完成后再由主线程交叉核查冲突；不能为了得到高分反复换评审。

独立评审应指出证据位置（文件与行号、截图区域、测试步骤）、严重度、影响和最小修正建议。由主线程判断是否属于任务范围；不要将个人审美差异或项目保留的例外判为缺陷。

### 可复用交接提示

> 请独立验收以下模块，不修改产品代码：{模块范围}。
> 用户需求与已确认风格：{原始需求、确认方向、明确例外}。
> 目标版本/文件：{提交、路径}；运行方式和测试数据：{本地入口、隔离夹具}。
> 原始证据：{视口与主题标注的截图、录屏、测试日志}。
> 按 rc-ui-style 的 acceptance.md 对适用检查项给出证据和0–5评分。区分静态/运行证据，未验证及不适用用N/A，不推断通过。返回阻断项、具体位置、复现步骤、影响与最小修正建议。若无法检查，说明原因与最小所需条件。不要推送、部署或操作真实用户数据。

### 汇总、修复与复验

主线程汇总各模块分数与证据，不只输出一个平均分；明确各项由谁检查、哪些使用回退。先核实互相矛盾的报告，再修正范围内的问题。影响共同tokens、布局或主题的改动，需要复验所有受影响模块，不仅复验报错的那一个按钮。

采用有界验收：按本次改动完成首轮，通常至多两轮修复复验。仍有阻断、缺少环境或范围扩大时，交代未解决项与下一步，不无限自我循环，也不为了结束而降低标准。用户另行要求持续处理时遵从其明确停止条件；没有独立环境不阻止提交诚实的部分结论。
